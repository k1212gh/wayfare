### 결론: **Qwen3.5 9B 를 기본으로 채택**

- 정확도 1위(후보 선택 87%, 비전 12장 중 오답 0)에 Gemma 4 보다 3배 빠르고 VRAM 도 5.5GB 로 여유가 있다.
- 한 모델이 텍스트와 이미지를 모두 받으므로 비전 모델을 따로 받을 필요가 없다 (7B 조합은 두 모델 10GB).
- 비전 응답이 가장 세밀하다: 삼성페이 시트를 `dialog`, "2km 이상 떨어진 매장" 확인창을 읽고 "퀵오더 주문 확인"으로 명명.
- 약점: 살짝 과감하다 — 제목이 없는 화면에서도 0번을 고른다(3건). 지점명("화성마도산업단지점")을 고른 1건은 피커에 지점명 거부 규칙을 추가해 막았다.
- 8GB 카드라면 같은 계열 `qwen3.5:4b` 가 다음 후보 (이번엔 미측정).

## 경로 문제: 왜 Ollama 네이티브 API 로 바꿨나

Ollama 의 OpenAI 호환 `/v1/chat/completions` 는 Qwen3.5 / Gemma 4 같은 thinking 모델에 `think:false` 를 전달하지 못한다.
같은 8노드 배치로 측정:

| 모델 | `/v1` (OpenAI 호환) | `/api/chat` 네이티브 (`think:false`) |
|---|---|---|
| qwen2.5:7b-instruct | 5.2s, 정상 | 5.4s, 정상 (동일 결과) |
| qwen3.5:9b | **48.3s, content 비어 있음** (추론 토큰이 max_tokens 소진) | 4.8s, 정상 |
| gemma4:12b | **73.6s, content 비어 있음** | 9.1s, 정상 |

→ `OpenAICompatClient` 는 base URL 에서 `/api/tags` 가 응답하면 자동으로 네이티브 경로를 쓴다 (`LLM_OLLAMA_NATIVE=0` 로 끌 수 있음). 비전은 `images:[base64]`, JSON 은 `format:"json"`. LM Studio / vLLM / llama.cpp 는 기존 `/v1` 그대로.

## 재현

```bash
# 모델 준비 (Ollama)
ollama pull qwen3.5:9b            # 권장
ollama pull gemma4:12b qwen2.5:7b-instruct qwen2.5vl:7b   # 비교용

# 벤치 (기준점 자동 생성: 현재 screen_map 에서 LLM 라벨 제거)
PYTHONPATH=. python scripts/bench_local_labels.py --tour <tour_id> \
    --models "qwen2.5:7b-instruct|qwen2.5vl:7b" "qwen3.5:9b" "gemma4:12b" --vision-limit 12
# 결과: workspace/bench_labels_<ts>.md / .json, 모델별 tour 는 workspace/bench_<모델>/ (대시보드에서 그래프 확인 가능)
# 정답표가 workspace/bench_gold_*.json 하나뿐이면 자동으로 채점
```

대시보드에서는 LLM 설정 → Ollama → 찾기 → 권장 모델(qwen3.5:9b)이 자동 선택된다.
